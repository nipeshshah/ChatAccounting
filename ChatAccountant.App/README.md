# Chat Accountant

Chat-style bookkeeping for small Indian businesses. Tap through a conversation to record income, expenses,
GST sales and purchases (cash or credit), settle debtors and creditors, print or share bills and statements,
and exchange transaction requests with the people you trade with.

## Run it

The app loads its pages from separate files, so it must be **served over http(s)** — opening `index.html`
by double-click will not work.

```bash
npm install        # only needed for the build tools and tests
npm start          # → http://localhost:8000   (or: python3 -m http.server 8000)
```

It starts in **demo mode** (data kept in this browser, Google sign-in simulated; mobile-verification code `123456`).
No build step is needed to run it — the compiled CSS and vendored libraries are committed.

## Switch to the real database (Supabase)

1. Run `database/supabase_schema.sql` once (Supabase → SQL Editor).
2. Enable Google (and Phone, for requests) under Authentication → Providers.
3. Edit **`js/config.js`**: set `provider: "supabase"` and fill in `SUPABASE_CONFIG` (project URL + anon key).

The anon key is public by design; row-level security in the schema protects each user's data.
Never put the service-role key anywhere in this project.

## Project structure

```
index.html                 page shell: <head>, stylesheet links, and <div data-include> slots
manifest.webmanifest       installable-app metadata
partials/                  HTML, one file per screen / region
  header.html  nav.html  undo-toast.html
  pages/   chat · manage · reporting · requests · profile · settings
  screens/ splash · lock · login
css/
  tailwind.css             GENERATED by `npm run build:css` (from tailwind.input.css + tailwind.config.js)
  base.css                 page, app frame, safe areas
  components.css           manage tabs, bottom-nav tabs
  touch.css                44px tap targets, readable text sizes
  fullscreen.css           full-screen chat mode
  documents.css            printed / shared bills & statements (3 Inch, A4, A5)
  print.css                @media print — only the document is printed, on white
js/
  config.js                ← the one file you edit: data provider + keys
  loader.js                fetches partials, then loads the scripts below in order
  data/                    data layer: panel.js (promise layer + write queue),
                           database_dummy.js (demo) and database_supabase.js (live) share one contract
  core/                    utils · state · chat-ui · summary · sync-status
  flows/                   chat conversations: shared pickers · review-undo · income-expense ·
                           received-paid · sale-purchase · view · setup-wizard · main-menu
  features/                export-csv · statement · reporting (report engine)
  print/                   modes · words · bill · statement-doc · output (print + share as PDF) · whatsapp
  pages/                   navigation · lock-screen · settings · manage · party-sync · requests · reporting · profile
  app.js                   boot: splash → sign-in → load data → start
assets/
  images/                  PNG logos, icons, favicon (regenerate with `npm run build:images`)
  vendor/                  jQuery, Phosphor icon fonts, html2canvas, jsPDF (refresh with `npm run vendor`)
database/supabase_schema.sql   tables, row-level security, request + lookup functions
scripts/                   serve.js · build-images.js · copy-vendor.js
tests/smoke.js             end-to-end test in a simulated browser (`npm test`)
tests/pdf-browser.js       generates the real bill / statement PDFs in headless Chromium and checks them (`npm run test:pdf`)
```

### How the scripts fit together

The JavaScript is plain browser scripts (no bundler). They share one global scope, so each file adds
functions and state that the others call, and **load order matters** — it is listed once, in `js/loader.js`.
`data/` loads first, then `core/`, `print/`, `flows/`, `features/`, `pages/`, and `app.js` last.
If you add a file, add it to the list in `loader.js`.

The data layer is the only code that knows where data lives. The pages call `Panel.*`; `Panel` calls
`window.Database`. A new backend only has to implement the contract documented at the top of
`js/data/database_dummy.js`.

## Common tasks

| Task | Command |
|---|---|
| Rebuild CSS after changing classes in HTML/JS | `npm run build:css` (or `npm run watch:css`) |
| Regenerate the PNG logo and icons | `npm run build:images` |
| Re-copy vendored libraries after an upgrade | `npm run vendor` |
| Run the end-to-end test | `npm test` |
| Prove the PDFs are real and not empty (real headless Chromium) | `npm run test:pdf` |

Tailwind scans `index.html`, `partials/` and `js/` for class names, so classes written inside JS strings
are included. If a style looks missing after you add a new class, rebuild the CSS.

## Notes

- Fonts (Plus Jakarta Sans, JetBrains Mono) come from Google Fonts; everything else is local.
- Sharing a bill or statement builds a PDF in the browser (html2canvas + jsPDF), loaded on first use.
- **WhatsApp bills** upload the PDF to a private Supabase Storage bucket (created by `database/supabase_schema.sql`) and open
  WhatsApp on the customer's chat with a link valid for 30 days. In demo mode there is nowhere to host the file, so it falls
  back to the phone's share sheet.
- To deploy, publish the folder as-is to any static host (GitHub Pages, Netlify, Cloudflare Pages…).
  Commit `css/tailwind.css` and `assets/` — they are not rebuilt on the server.
